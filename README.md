## 🔥 ما الجديد في التحديث (v5.1)؟

### 1️⃣ حل جذري ونهائي لمشكلة الانتقال أو الرجوع المبكر لغرفة الزعيم (`3D Bounding Box Room Order + Boss Cluster Filter`) 🚪🚫💀
- **لماذا كان السكربت في `v5.0` ينتقل أو يرجع لغرفة الزعيم مباشرة؟**
  1. بفحص لقطة الشاشة المكبرة داخل ساحة الزعيم الدائرية (الغرفة رقم `5` الملاصقة للجدار الأيسر للغرفة الأولى `1`)، تبيّن أن زعيم الفصل الأول (`InfestedBeast`) يقف بجانب الجدار المشترك مع الغرفة الأولى ويوجد تحته مباشرة كائن/وحش ثانٍ مضاء باللون البنفسجي (`< 15` خطوات منه)، مما جعل عدد الجيران `neighbors >= 1` في ساحة الزعيم فلم يتم اعتباره زعيماً منعزلاً!
  2. كما أن استخدام `hadEnt ~= false` في Lua كان يعامل أي وحش أو زعيم قيمته `hadEntrance == nil` على أنه داخل الغرفة المفتوحة الحالية إذا كان قريباً من الجدار (`<= 75` خطوة)، فيقوم السكربت بحفظ إحداثيات ساحة الزعيم داخل `PB_LastActiveRoomPos`، وعند محاولة الرجوع من الغرفة المقفلة يعيد اللاعب إلى داخل ساحة الزعيم مرة أخرى!
  3. كما كان الوحش المحظور (`isLockedBoss`) يوضع داخل `nextBossMob` فيعود إليه السكربت بعد `0.15` ثانية إذا لم تكن وحوش الغرفة الثانية قد ظهرت بعد.
- **الحل الجذري في `v5.1`**:
  - **تحديد رقم الغرفة الفعلي هندسياً (`getPBRoomBoundingBox` + `getPBPointRoomNumber`)**: يفحص الصندوق ثلاثي الأبعاد (`GetBoundingBox`) لكل غرفة مرقمة (`workspace["1"]` إلى `workspace["25"]`) لمعرفة الغرفة التي يقع الوحش بداخلها فعلياً (`1 -> 2 -> 3 -> 4 -> 5`) دون أن ينخدع بكبر حجم ساحة الزعيم الدائرية الملاصقة للغرفة الأولى.
  - **عزل الزعيم ومرافقيه (`Boss Anchor + 65-Stud Cluster Filter`)**: إضافة `InfestedBeast` و `FleshGiant` و `Gatekeeper` و `BloodDemon` وغيرها إلى قائمة الزعماء، واعتبار أي وحش صحته `> 1.35x` من الوحوش العادية زعيماً، وعزل أي كائن يقع ضمن `65` خطوة من الزعيم حتى لا يتم اختيار الوحش الصغير الموجود تحت الزعيم.
  - **استبعاد صارم للزعيم المقفل (`not c.isLockedBoss`) + التنقل المتسلسل للغرف (`2 -> 3 -> 4`)**: لا يمكن وضع أي زعيم مقفل في `nextBossMob` نهائياً حتى يتم دخول وتصفية غرفة جديدة مفتوحة (`hadEntrance == true`)، وإذا كانت الغرفة التالية تتطلب دخول اللاعب إليها لتوليد الوحوش، ينتقل السكربت تلقائياً بالترتيب (`2` ثم `3` ثم `4`) قبل غرفة الزعيم.

### 2️⃣ تفعيل سحب وتجميع الأعداء في مكان واحد وضربهم مع تفريم الدنجن (`Bring Mobs + Dungeon Auto-Farm`) 🧲⚔️
- **سبب المشكلة في `v5.0`**:
  - كان السطر `if Config.PB_BringMobs and not isAutoFarming` يعطل ميزة **سحب الوحوش (`Bring Mobs`)** بالكامل بمجرد تشغيل **تفريم الدنجن (`Auto Farm Dungeon`)**!
- **الحل في `v5.1`**:
  - أصبحت ميزة **سحب وتجميع الأعداء (`PB_BringMobs`)** مفعلة افتراضياً وتعمل بتناغم كامل مع **تفريم الدنجن**: تقوم بسحب جميع أعداء الغرفة المفتوحة الحالية (`hadEntrance == true` ضمن `85` خطوة) وتجميعهم في نقطة واحدة أمام سيف اللاعب مباشرة (`activeFollowPart.CFrame` على بُعد `6.0` خطوات أمام اللاعب وظهورهم باتجاه اللاعب) مع توسيع الـ `basehitbox` وضربهم وشل حركتهم جميعاً في نفس اللحظة بالسيف والأوتو كليكر!
